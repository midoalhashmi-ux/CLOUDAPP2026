## 1. نبذة عن المشروع
منظومة محتوى رياضي مبنية بـ **Flutter** ومربوطة بـ **Firebase**، وتتكون من:

1. **تطبيق المحتوى** (هذا المشروع): يعرض الأقسام والقنوات والمعلومات فقط.
2. **تطبيق مشغل منفصل**: يستقبل القناة المختارة ويشغّل البث المرخّص.
3. **لوحة تحكم ويب منفصلة**: يدير المالك منها كل المحتوى دون تحديث التطبيق.

الهدف هو أن يضغط المستخدم قناة في تطبيق المحتوى، فيفتحها مباشرة في تطبيق المشغل
المنفصل. لا يحتوي تطبيق المحتوى على رابط البث الحقيقي إطلاقاً.

**المستخدم مالك المشروع لا يكتب كود بنفسه** — التطوير بالكامل يتم بمساعدة الذكاء
الاصطناعي، لذلك الوضوح في هذا الملف أهم من أي شي ثاني.

## 2. القرارات المتفق عليها (لا تُغيّر بدون سؤال المستخدم)

| القرار | التفاصيل |
|---|---|
| لوحة التحكم | تطبيق **ويب منفصل تماماً** عن تطبيق الموبايل |
| تطبيق المحتوى | تطبيق مستقل يعرض الأقسام والقنوات فقط، ولا يشغّل البث داخل نفسه بعد اعتماد المعمارية الجديدة |
| تطبيق المشغل | تطبيق أندرويد منفصل يثبت من المتجر/مصدر رسمي، وهو الوحيد الذي يشغّل البث المرخّص |
| انتقال القناة للمشغل | عند نقر قناة: تطبيق المحتوى يفتح رابطاً داخلياً (Deep Link / Android Intent) إلى المشغل، ويرسل `channelId` فقط. المشغل يجلب البث من الخادم بعد التحقق |
| عدم وجود المشغل | يعرض تطبيق المحتوى رسالة واضحة مع زر للانتقال إلى صفحة تثبيت المشغل؛ لا يحاول فتح رابط بث داخل تطبيق المحتوى |
| صلاحيات لوحة التحكم | مستخدم واحد فقط (المالك) — لا حاجة لأدوار متعددة حالياً |
| حماية روابط البث | رابط البث الحقيقي **لا يصل لتطبيق المحتوى أبداً**. المشغل وحده يطلب توكن/رابط مؤقت من **Cloud Function** أو الخادم الخاص. روابط ومصادر البث يجب أن تكون مرخّصة ومملوكة للمالك |
| الإعلانات (AdMob) | تُفعّل/تُغلق بالكامل من لوحة التحكم في أي وقت |
| الأقسام (Categories) | تُضاف/تُحذف/تُعدّل بالكامل من لوحة التحكم (نص + صورة لكل قسم) |
| الإشعارات | ميزة اختيارية، تُفعّل من لوحة التحكم عند الحاجة |
| وضع الصيانة | زر في لوحة التحكم يقفل التطبيق مؤقتاً برسالة مخصصة |
| الإحصائيات | تتبع بسيط لعدد المشاهدات لكل قناة |
| اللغة | عربي فقط، بدون تعدد لغات |
| محتوى المشتركين المدفوعين | أيقونة **ظاهرة وعادية** باسم "اشتراك" في التطبيق، تطلب كود اشتراك يُتحقق منه عبر Firestore. الأقسام الخاصة مخفية من القائمة الرئيسية ولا تظهر إلا بعد التحقق. **تم تجنب أي إخفاء يهدف لخداع فحص Google Play لأنه مخالفة سياسات وقد يسبب تعليق الحساب بالكامل** |
| التصميم | عصري (Modern UI)، وقابل للتغيير أونلاين بالكامل عبر لوحة التحكم بدون تحديث التطبيق (ألوان، خلفيات، وشكل عام لاحقاً) |

## 5. هيكل بيانات Firestore
```
settings/theme        → { primaryColor, backgroundColor, backgroundImageUrl }
settings/features     → { matchAlerts, liveScoreTab, backgroundAudio, liveChat, adsEnabled, maintenanceMode, maintenanceMessage }
categories/{id}       → { title, order, iconUrl, parentId, isPremium }
channels/{id}         → { categoryId, title, subtitle, status, startTime, logoUrl, viewCount, playerChannelKey }
privateStreams/{id}   → { sourceUrl, provider, active }  // قراءة الخادم/Cloud Function فقط؛ ممنوع على تطبيق المحتوى
settings/player       → { androidPackage, deepLinkScheme, storeUrl, minimumPlayerVersion }
subscriptions/{code}  → { active, createdAt, expiresAt, unlockedCategoryIds }
```

### عقد الربط بين تطبيق المحتوى والمشغل

> ✅ الاسم معتمد ومطبّق في الكود (2026-08-25).

```
اسم حزمة المشغل (Application ID): com.midoalhashmi.zoltrastream

المحتوى يفتح المشغل بالترتيب:
1. Android Intent صريح (action_view + package=com.midoalhashmi.zoltrastream)
2. رابط داخلي عام كخطة بديلة: sportsplayer://play?channelId=<Firestore-channel-id>
3. رسالة + رابط تحميل من المتجر إن فشل الاثنان

كلا الاسمين (الحزمة + الرابط الداخلي) قابلان للتغيير من لوحة التحكم
(settings/player.androidPackage و settings/player.deepLinkScheme) بدون
تحديث تطبيق المحتوى.

المحتوى يرسل فقط:
- channelId
- requestId اختياري لمنع إعادة الطلب

المحتوى لا يرسل أبداً:
- sourceUrl
- رابط HLS/M3U8
- توكن البث
- بيانات دخول السيرفر
```

مسؤوليات المشغل:

1. يتحقق من أن الطلب صالح.
2. يرسل `channelId` إلى Cloud Function أو API السيرفر الخاص عبر HTTPS.
3. يحصل على رابط جلسة مؤقت للمالك المرخّص فقط.
4. يشغّل HLS ويدعم رسالة خطأ وإعادة محاولة واختيار جودة عندما يتيح المصدر ذلك.

### متطلبات نشر آمنة

- مصدر كل قناة يجب أن يكون مملوكاً أو مرخّصاً للمالك.
- لا تضع رابط البث في GitHub أو Firestore العام أو داخل تطبيق المحتوى.
- يتطلب إصدار روابط مؤقتة من Cloud Function عادة تفعيل Blaze Plan، أو استخدام API السيرفر الخاص بالمالك.
- قبل نشر المشغل، أضف رابط صفحة المتجر/التثبيت إلى `settings/player` ليتمكن تطبيق المحتوى من إرشاد المستخدم إذا لم يكن المشغل مثبتاً.

## 8. قواعد توفير التوكن (إلزامية لأي نموذج يعمل على المشروع)
المستخدم يعمل من الجوال فقط بدون بيئة تطوير، ويرفع/ينزّل الملفات يدوياً عبر واجهة
GitHub، لذلك التحكم في استهلاك التوكن مهم جداً حتى لا تتوقف المحادثة قبل إكمال
الخطوة.

- **لا تُخرج المشروع كاملاً أبداً.** عند تنفيذ خطوة، أخرج **فقط** الملفات الجديدة
  أو المعدّلة، كل ملف في كتلة كود منفصلة، وقبل كل كتلة اكتب **المسار الكامل**
  للملف كما هو داخل المشروع (مثال: `lib/features/live_score/live_score_service.dart`)
  حتى يستطيع المستخدم نسخه ورفعه مباشرة دون البحث عنه.
- **ملف واحد كبير أفضل من نقاش طويل.** إذا كان التعديل بسيطاً (سطر أو دالة)، صف
  التعديل ثم أعطِ الملف كاملاً بعد التعديل — لا تطلب من المستخدم "أضف هذا السطر
  في مكانه" لأنه لا يكتب كود بنفسه.
- **قسّم كل خطوة كبيرة من خارطة الطريق (القسم 4) إلى خطوات فرعية صغيرة**، ونفّذ
  خطوة فرعية واحدة فقط في كل رد، بدل محاولة إنجاز الخطوة كاملة دفعة واحدة.
- **لا تُعد شرح أو تلخيص المشروع في كل رد.** هذا الملف هو المرجع؛ إذا احتجت
  السياق راجعه، ولا تكرره في ردودك للمستخدم.
- **إذا طال النقاش في محادثة واحدة واقترب من حد التوكن**، انصح المستخدم بفتح
